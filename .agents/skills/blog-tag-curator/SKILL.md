# 博客标签治理与高维打标技能 (Blog Tag Curator)

本技能用于解决博客打标中最常见的问题：**将“文章字面高频词/具体案例载体”误当作“标签”**。
核心原则：**全文搜索解决“字面匹配”，标签解决“跨题材概念聚类”。**

---

## 一、核心认知框架：三步向上抽象法

在为任何文章（无论是历史迁移文章清洗，还是新文章发布）生成或重构标签时，**严禁直接提取文中高频出现的名词或实体**，必须依次执行以下三步抽象：

### 第 1 步：剥离案例载体（禁词过滤）
先在脑海中删去文章里的具体人名、地名、机构名、产品名和事件载体，以下类别**一律禁止作为标签**：
1. **具体实体/品牌/产品名**：如 `榕树下`、`PALM`、`商务通`、`万科`、`绿城`。
2. **具体身份/人群/学段字面词**：如 `留学生`、`学生`、`高中`、`大学`、`员工`、`胖友`、`老板`。
3. **具体国家/城市地名**：如 `新西兰`、`美国`、`奥克兰`、`成都`、`上海`（除非未来专门设立区域研究索引，否则一律转化为背后的议题，如 `跨文化适应`、`教育`、`社会观察`）。
4. **栏目名或旧系列名**：如 `逸峰闲话`、`业主维权`、`五千年架构师`、`学择新西兰`（栏目由目录或 `series` 承载，绝不放入 `tags`）。
5. **情绪词或宽泛废词**：如 `常识`、`感悟`、`杂谈`、`企业`（太宽泛，应具体到 `企业管理` 或 `创业`）。

### 第 2 步：三层高维映射（每篇 3–5 个标签）
即便正文中**一次都没有出现某个词**，只要文章内核属于该范畴，就应当打上该高维标签。每篇文章的 3–5 个标签必须由以下三层构成：

1. **领域标签（Domain，1–2 个）**——回答“这篇文章属于人类知识/社会议题的哪个抽屉？”
   * 例：讲留学生选课、寄宿家庭、择校 $\rightarrow$ `教育`、`跨文化适应`
   * 例：讲商务通与 PALM 的市场竞争 $\rightarrow$ `产品逻辑`、`技术史`
   * 例：讲榕树下早期团队分工与让位 $\rightarrow$ `企业管理`
2. **方法论 / 视角标签（Methodology，0–1 个）**——回答“作者用什么手术刀去解剖这件事？”
   * 优先从 `[global].preferred_method_tags` 及栏目方法论中选取：
   * 例：`制度设计`、`程序正义`、`程序合规`、`共同治理`、`管理实践`、`组织变革`、`架构治理`、`史料辨伪`、`媒体辨伪`、`复杂系统`
3. **核心主题标签（Core Topic，1–2 个）**——回答“这篇文章聚焦什么可复用的具体议题？”
   * 例：`家庭教育`、`创业`、`公共收益`、`物业合同`、`安全工程`、`国家能力`

### 第 3 步：跨题材复用度检验与白名单对齐
* **复用度测试**：自问“未来半年写另一篇完全不同具体事件的文章时，还会不会用到这个标签？”如果不会，说明还不够抽象，继续向上提炼一层。
* **白名单对齐**：始终对照 [data/tag-whitelist.toml](../../../data/tag-whitelist.toml) 中的 `allowed` 列表与 `aliases` 归并表，确保全站规范标签总量控制在 `max_total_tags`（60 个）以内。

## 三、标准工作流（Workflows）

本技能提供配套脚本 [tag_manager.py](./scripts/tag_manager.py) 来执行全站扫描、批次读取和无损写回 Front Matter。

### 工作流 1：全局盘点与白名单演进（Audit & Whitelist Upgrade）
当需要开始清洗或定期（每半年）审查标签体系时执行：

1. **运行全局盘点脚本**：
   ```bash
   python3 .agents/skills/blog-tag-curator/scripts/tag_manager.py audit
   ```
2. **分析非白名单高频词与孤岛标签**：
   * 识别哪些高频非白名单标签属于应当吸纳进 [data/tag-whitelist.toml](../../../data/tag-whitelist.toml) 的**高维领域/主题词**（例如：`教育`、`家庭教育`、`跨文化适应`、`创业` 等）。
   * 识别哪些标签属于同义词，应补充进 `[aliases]`（例如：`"管理" = "企业管理"`）。
   * 识别哪些属于具体载体词/旧栏目名，应在后续批次清洗中剔除。
3. **更新白名单**：编辑 [data/tag-whitelist.toml](../../../data/tag-whitelist.toml)，确保各栏目 `allowed` 总数（去重后）不超过 60 个。

### 工作流 2：分批交互式清洗与重构（Batch Interactive Refactoring）
对存量文章进行标签重构时，**严禁一次性盲改全站文件**，必须采用**每批 10–15 篇**的交互式审阅流程：

1. **提取下一批待清洗文章（含正文摘要）**：
   ```bash
   python3 .agents/skills/blog-tag-curator/scripts/tag_manager.py batch --limit 12
   ```
   *可通过 `--section yifeng-talks`、`--tag "学择新西兰"` 或 `--offset N` 指定批次范围。默认优先筛选含有非白名单标签或标签数量不合规（<3 或 >5）的文章。*
2. **逐篇阅读并按“三步向上抽象法”拟定新标签**：
   * 必须结合文章标题与正文实际内容判断，不得仅凭旧标签字面替换。
   * 输出如下格式的审阅表格给用户确认：
     ```markdown
     | # | 文章标题 (路径) | 原标签 (诊断) | 建议新标签 (3-5个) | 向上抽象逻辑 |
     |---|---|---|---|---|
     | 1 | [标题](file:///...) | `旧1`, `旧2` (字面实体/旧栏目) | `新1`, `新2`, `新3` | 简述文章内核及抽象理由 |
     ```
3. **等待用户确认或微调**：
   * 用户可以说“全部确认”，也可以针对某几篇提出修改（如“第 3 篇加上‘制度设计’”）。
4. **无损写回确认后的标签**：
   使用脚本的 `apply` 子命令将确认后的标签写回对应 Markdown 文件（保持原文件其余 Front Matter 与正文完好无损）：
   ```bash
   python3 .agents/skills/blog-tag-curator/scripts/tag_manager.py apply --json '<JSON数组>'
   ```
5. **汇报进度并询问是否继续下一批**。

### 工作流 3：日常新文章高维打标（New Post Tagging）
当用户按 [AGENTS.md](../../../AGENTS.md) 的固定发文流程发布新文章且 `标签：自动`（或请求推荐标签）时：
1. 先读取 [data/tag-whitelist.toml](../../../data/tag-whitelist.toml) 最新白名单。
2. 对照正文执行“三步向上抽象法”，从白名单中挑选 1–2 个领域标签 + 0–1 个方法论标签 + 1–2 个核心主题标签（共 3–5 个）。
3. 绝不因为正文反复出现某个专有名词而将其设为标签。
